# Map and artifact parity with the installed game

The 2026-11-02 audit inspected Stardew Valley **1.6.15.24356**, DLL SHA-256
`f3e97f01d3fd2b1e6094fc8d2b59950aa6cb9d6cd1bf1b39d72d58edda8aad12`.
Bubble and artifact entry points now require the inspected version instead of
assuming that uninspected 1.6.x builds share these rules.

## Independent evidence

`tests/fixtures/game-map-rules.json` was captured in .NET 6 using the installed
assembly's unmodified `Utility.CreateRandom`, `FishingRod.distanceToLand` and
`Farmer.DailyLuck`. The map-distance calls used actual XNB/tBIN map data decoded
by the installed xTile assembly. The fixture records the DLL and source-map
hashes. It contains observations, not values generated by the Python predictor.

For the two end-time observations, the capture applies the termination predicate
from `GameLocation.performTenMinuteUpdate` to draws returned by the real
`Utility.CreateRandom`. This is a focused numerical oracle, not a recording of
a complete game session. The capture did not load or modify the user's save.

The audit additionally compared Water, NoFishing and open-water classification
across all eleven bundled map exports against the installed XNB maps. Six
Mountain tile-instance NoFishing properties were missing from the old export;
these are now included explicitly with their source hash in
`maps.provenance.json`.

## Corrected behavior

- Frenzy attempts have probability 0.008 at the Beach and 0.01 in the other
  eligible locations. The successful frenzy branch cannot expire until more
  than 120 minutes have elapsed; ordinary bubbles use more than 60 minutes.
- Early eligibility counts entries in `fishCaught`, not fishing attempts.
  Calendar age follows the game's date, independently of `daysPlayed`, which
  remains an RNG seed input.
- The game's fish selection runs on the session RNG and rejects trash and
  legendary fish. Forecasts therefore branch into ordinary bubbles and a
  conditional frenzy. Every subsequent event is computed within its branch.
  Equal events shared by all branches have no scenario label; conditional
  events retain their required decisions in JSON, text and PNG legends.
  Branches are hypotheses, not claims that each fish-selection outcome is
  reachable under every set of live equipment/weather conditions.
- More than 64 timelines for one location produce an explicit unavailability
  diagnostic rather than silently selecting or truncating a branch.
- Water geometry includes the zero row and column, preserves the first tile
  of each tileset, and resolves global GIDs to local indices before applying
  the game's outdoors-tilesheet exclusions. Tile-instance properties are
  retained. Saved placed objects also block water spawn candidates.
- Artifact luck uses the effective luck of the online farmers, including
  the float32 Special Charm bonus and the game's clamp. Solo saves have an
  unambiguous online set. Multiplayer saves require an explicit set in the
  domain call; ordinary analysis reports unavailability when it is unknown.
- Desert Festival artifact spots receive the independent 3–6 Calico Egg drop
  before the base drop. A retained festival map outside Spring 15–17 is
  reported as inactive, with no prediction for an inaccessible dig.
- Artifact query mail checks include pending mail. Unknown player/location
  selectors are rejected instead of silently interpreted as the host/current
  location. Notes already exhausted by the seen list and inventory are
  resolved to the fallback item, eliminating an impossible random alternative.

## Historical fixtures

The 2,772 bubble fixtures were generated from the retired C# predictor, not
from the game. Their role is arithmetic regression where its rules agree with
the inspected game.

The historical fixture's year was always two, even for early daysPlayed;
compatibility tests normalize the synthetic calendar and provide an explicit
distinct-fish eligibility count. This normalization is only in the test adapter;
real saves retain their date and fish collection independently.

The following historical outputs are intentionally not asserted as game truth:

- 792 cases using signed Int64 extrema, whose old integer-exact seed handling
  differs from the DLL's double conversion;
- unconditional-frenzy cases and cases which relied on the omitted zero border.

The tests label these cases with explicit skip reasons. The independent game
seed fixture covers numeric boundaries; `test_map_game_rules.py` covers
frenzy branches, probability, timing, eligibility, map borders, tile identity,
saved occupancy, rendering, artifact luck, online selection, festival drops,
mail queries and note exhaustion.

All 100 historical DesertFestival artifact cases use Summer 16, when the map
is inactive. Their regression now verifies inaccessibility rather than retaining
the prior port's hypothetical drops.

## Remaining boundaries

An artifact result means **the host's next dig with the saved state**. A digging
route can increment ArtifactSpotsDug, award DefenseBookDropped, consume notes
and change later results; it is not simulated. Future skill buffs and equipment
changes must not be inferred from the save.

The static map model includes saved placed objects but does not reconstruct
every live building/map override. Panning is a separate, unsupported prediction;
its draws happen after the bubble calculation for a tick and do not retroactively
change that tick's bubbles. Mods and uninspected game versions need their own
data and rule verification.

The old source fixtures remain unchanged as historical evidence. New results
should be checked against the game-derived observations and explicit scenarios,
not made to match a demonstrated defect in the earlier predictor.

## Second pass: location contexts and predicate precision

The second pass calls the installed DLL's unmodified
`GameLocation.GetLocationContextId`, `GameLocation.GetSeason` and
`GameStateQuery.Helpers.RandomImpl`. `tests/fixtures/game-artifact-contexts.json`
records observations for 80 original xTile maps, the map hashes and the
LocationContexts XNB hash. The query observation supplies a controlled draw
`858993460 / 2147483647`; it is a predicate boundary probe, not a captured save's
random sequence or a complete `digUpArtifactSpot` execution.

- Desert and DesertFestival use the Desert context's summer override. They
  must not use the valley's spring/winter artifact conditions. The explicit
  map-level summer overrides on island maps take priority over context data.
  Exported context data is honored when supplied; otherwise the inspected
  vanilla context profile is used. An uninspected location name or a missing
  required context produces a diagnostic rather than a guessed season.
- The `RANDOM` query parses its chance as float32. The controlled draw above
  passes `RANDOM 0.4` in the DLL, while comparison with Python's float64 `0.4`
  rejects it. The predictor now uses the game's precision.
- Island behavior follows inspected map context and class inheritance rather
  than an `Island` name prefix. Caldera uses journal scraps and the independent
  IslandLocation artifact bonus. IslandFarmHouse is in the island context but
  does not inherit that bonus override.
- Online average luck uses explicit left-to-right addition, matching
  `FarmerTeam.AverageDailyLuck`. A separate call to that unmodified method with
  five charmed farmers followed by an uncharmed farmer, base luck -0.008,
  returned `0.012833333643774189`. Python's compensated `sum` returns a value
  one ULP higher for this case.

Comparison with the immediately preceding predictor found **no changed drops
among Sunny's 11 saved spots** on Spring 11, year 2. The retained DesertFestival
spot remains inactive. Counterfactual Desert (10,37) on the same date changes
from Rice Shoots x2 to Clay x3; Desert (10,28) on Winter 11, year 2 changes from
Winter Root x1 to Clay x3. These are demonstrations using the corrected game
predicate, not recordings of the user digging those spots.

The evidence validates specific seed, geometry, context and predicate rules.
It does not prove every full artifact-drop path or a whole day's live bubble
history. Historical predictor fixtures remain regression tests only. Live map
overrides, a changed object layout, buffs and unsaved session RNG still bound
the predictions. There is also no single next artifact spot in a save: each
saved spot is an alternative next action, and XML order is not a digging route.
